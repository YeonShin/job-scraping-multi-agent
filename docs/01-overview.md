# 1. 시스템 개요 (System Overview)

## 1.1 프로젝트 정의 및 비전
본 프로젝트는 **야간 자동화(Nightly Batch)**를 통해 주요 채용 사이트의 웹 개발 직무 공고를 사람처럼 탐색·수집하고, 고품질 데이터로 정제·구조화하여 **노션(Notion) 데이터베이스에 자동으로 페이지를 발행하는 '3-Tier 자율 에이전트 파이프라인'**을 구축하는 것을 목표로 합니다.

사용자가 잠든 사이(새벽) 독립된 서브에이전트들이 브라우저를 조작하고 공고를 분석하여, 아침에 일어났을 때 노션에서 정갈하게 정리된 신규 채용공고 리포트를 바로 검토할 수 있는 무중단 경험을 제공합니다.

---

## 1.2 기존 크롤러 방식의 한계와 AI 에이전트 도입 배경

| 구분 | 기존 규칙 기반(Rule-based) 스크래퍼 | 본 프로젝트의 AI 에이전트 파이프라인 |
| :--- | :--- | :--- |
| **사이트 UI 개편 대응** | 셀렉터(CSS/XPath) 변경 시 에러 발생 및 수동 코드 수정 필요 | 시각/접근성 트리 기반으로 스스로 UI를 이해하고 자율 적응 (Zero-Maintenance) |
| **팝업 및 예외 상황** | 팝업, 광고, 쿠키 동의 창 등장 시 멈춤 현상 발생 | 에이전트의 상황 인지 판단으로 유연하게 닫기/스킵 처리 |
| **통이미지 공고** | 텍스트가 없어 내용 수집 불가 (공란 처리) | 멀티모달 Vision LLM을 결합하여 이미지 내 자격요건 OCR 추출 |
| **대규모 공채 분류** | 제목에 직무가 없으면 누락되거나 불필요한 직무까지 수집 | 공고 본문을 심층 분석하여 '웹 개발' 부문만 정밀 발췌 |
| **봇 차단(Cloudflare 등)** | 헤드리스 브라우저 특성 감지로 IP/기기 즉시 차단 | CDP 원격 디버깅 및 영구 프로필 연동으로 실제 사용자 환경 재현 |

## 1.3 핵심 목표 (Key Objectives)

1. **완전 자율 브라우징 (Autonomous Browsing via MCP)**
   - Playwright MCP를 통해 에이전트가 브라우저 탭을 열고, 페이지를 탐색하며, 필요한 정보를 사람처럼 판단하여 수집.
2. **비용 및 속도 최적화 (Token & Concurrency Optimization)**
   - 3-Tier 계층 분업을 통해 에이전트의 컨텍스트 윈도우 오염 방지.
   - 노션 기존 DB 사전 대조로 불필요한 브라우저 접근 비용 70~80% 절감.
   - 동시 실행 워커 풀(Worker Pool)을 통한 병렬 수집.
3. **노션 템플릿 규격화 및 알림 자동화 (Normalized Notion & Discord Alerts)**
   - 자격요건, 우대사항, 기술스택, 마감일, 링크, 담당업무 등을 단일한 표준 노션 스키마로 가공하여 등록.
   - 배치 작업 완료 즉시 **디스코드 웹훅(Discord Webhook)**으로 일일 수집 요약 리포트와 신규 공고 하이라이트를 실시간 메시지로 전송.
4. **견고한 하네스 엔지니어링 (Robust Harness Engineering)**
   - 시간 초과, 사이트 오류, 예외 상황 발생 시 전체 파이프라인이 중단되지 않는 회복 탄력성(Fault Tolerance) 확보.
