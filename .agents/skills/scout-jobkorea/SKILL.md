# Jobkorea Scout Sub-Agent

잡코리아 플랫폼의 직무별 채용정보(`menucode=duty`)에서 기업 형태와 직무 범위에 맞춘 **2가지 분기(Dual-Track) 탐색 전략**을 수행합니다.

---

## 1. 듀얼 트랙 탐색 규격 및 브라우저 필터링 프로토콜

> 🚨 **[중요: 잡코리아 필터링 메커니즘]**  
> 잡코리아 직무별 채용정보(`joblist?menucode=duty`)는 **URL 쿼리 파라미터로 필터 조건이 적용되지 않는 구조**입니다.  
> 따라서 서브에이전트는 반드시 기본 URL로 브라우저 진입 후 **필터 UI(직무, 경력, 기업구분)를 직접 클릭하여 필터를 설정**해야 합니다.

* **기본 진입 URL**: `https://www.jobkorea.co.kr/recruit/joblist?menucode=duty`

---

### [분기 1] 대기업 / 중견기업 / 매출1000대 / 30대그룹사 / 강소기업 트랙 (SW전체)
1. **직무 선택 (Duty)**:
   - `IT·인터넷` 대분류 선택
   - AI·개발·데이터 주요 직군 체크: `프론트엔드개발자`, `웹개발자`, `백엔드개발자`, `앱개발자`, `시스템엔지니어`, `소프트웨어개발자`, `웹퍼블리셔`, `AI서비스개발자`
2. **경력 조건 (Career)**:
   - `신입`, `경력무관` 체크
3. **기업 형태 (Company Type)**:
   - `대기업`, `30대그룹사`, `중견기업`, `매출1000대기업`, `강소기업` 체크
4. **결과 조회**:
   - `선택된 조건 검색하기` (또는 검색 버튼) 클릭하여 목록 갱신

* **정렬 기준**: 최신 등록순

---

### [분기 2] 웹개발자 / 프론트엔드 / 웹퍼블리셔 트랙 (기업규모 무관)
1. **직무 선택 (Duty)**:
   - `IT·인터넷` 대분류 선택
   - 핵심 3개 직무만 선택: `프론트엔드개발자`, `웹개발자`, `웹퍼블리셔`
2. **경력 조건 (Career)**:
   - `신입`, `경력무관` 체크
3. **결과 조회**:
   - 검색 버튼 클릭하여 목록 갱신

* **정렬 기준**: 최신 등록순

## 2. 공고 목록 타깃팅 및 광고 배제 (토큰·비용 최적화)
> 🚨 **[광고 필터링 필수]** 잡코리아 목록 상단의 스페셜/포커스 배너 광고는 필터와 무관한 공고가 섞여 있어 불필요한 토큰과 시간을 소모합니다.  
> 반드시 **일반 채용공고 리스트 영역인 `<div id="dev-gi-list">` 내부의 공고만 탐색**하십시오!

* **타깃 컨테이너**: `<div id="dev-gi-list">` (`#dev-gi-list`)
* **공고 식별**: 해당 컨테이너 내부의 `a[href*="GI_Read/"]` 태그를 통해 공고 고유 식별자 파싱.
* **상세 요강 접근**:
  `https://www.jobkorea.co.kr/Recruit/GI_Read/{id}`

---

## 3. 작업 절차 (Sub-Agent Workflow)
1. **브라우저 기반 3단계 구간 점프(Range Skip) 목록 탐색**:
   - `data/checkpoint.json`에서 `headJobId`(최신 앵커)와 `tailJobId`(과거 앵커)를 로드합니다.
   - `https://www.jobkorea.co.kr/recruit/joblist?menucode=duty` 진입 후 필터를 설정합니다.
   - **Phase 1 (신규 탐색)**: 1페이지 일반 공고(`#dev-gi-list`)부터 심사·등록하다가 `headJobId` 또는 `headWindow`를 만나면 신규 탐색을 완료합니다.
   - **Phase 2 (초고속 건너뛰기)**: 본문 열람을 중지하고, 하단 페이징 버튼(2, 3...)을 누르며 목록의 `GI_Read` 링크들 중 `tailJobId`가 나올 때까지 초고속으로 페이지를 넘깁니다 (토큰 소모 제로).
   - **Phase 3 (미지의 과거 탐색)**: `tailJobId` 다음 공고부터 다시 상세 요강 열람 및 정밀 심사를 재개하여 새로운 과거 공고를 지속 발굴합니다.
2. **중복 필터링 및 통계 누적**:
   - `notion-job-sync`의 기존 등록 캐시와 대조하여 이미 등록된 URL은 0.001초 만에 스킵(`skipped++`)하고, 전체 스캔 건수(`totalScanned++`)를 집계하며 종료 시 체크포인트를 갱신합니다.
3. **상세 본문 브라우징 및 심사**:
   - `browser_navigate` 또는 `browser_subagent`로 상세 페이지(`GI_Read/{id}`)에 진입하여 자격 요건, 우대 사항, 전형 단계를 파싱합니다.
   - 통이미지/배너 공고의 경우 `browser_screenshot`으로 캡처 후 문맥을 판독합니다.
   - **심사 기준**:
     * 대기업/그룹사: 일반 SW개발/시스템/AI 포지션도 합격.
     * 중소/벤처: 반드시 웹 프론트엔드, 웹 풀스택, 퍼블리셔 포지션이어야 합격 (순수 백엔드 탈락).
     * 공통: 최소 경력 2년 이상 요구 시 즉시 탈락.
4. **전형 절차 분해**: 1차~6차 채용 단계 추출 (`서류전형`, `코딩테스트`, `면접전형` 등).
5. **노션 등록 위임 (Envelope 패턴)**:
   - 심사 통과 건을 `stats` 메타데이터와 함께 `notion-job-sync` 스킬을 통해 노션 DB에 등록합니다.
6. **안전 종료 조건**:
   - 단일 세션 누적 검토 공고(`totalScanned`)가 2,000건을 초과하거나 사용자 지정 목표치에 도달하면 즉시 탐색을 종료하고 체크포인트를 갱신합니다.
